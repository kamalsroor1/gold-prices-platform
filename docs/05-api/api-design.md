# تصميم الواجهات البرمجية (API Design)

**لماذا هذا الملف موجود؟**
يوضح هذا الملف الفلسفة العامة لتصميم الـ APIs، لضمان اتساق الواجهات، سهولة استهلاكها من قبل تطبيق Flutter، وتوافقها مع قيود الأداء الخاصة بـ Hostinger.

## الفلسفة التصميمية:
1. **RESTful:** الاعتماد على مبادئ REST لضمان قابلية التوسع والوضوح.
2. **الكفاءة (Performance):** تقليل حجم البيانات المتبادلة (Payload) والاعتماد على الكاش لتخفيف الضغط على السيرفر.
3. **التسمية:** استخدام إصدارات للـ APIs (`/api/v1/`) لضمان التوافق المستقبلي.

## المفاضلات (Trade-offs):
- استخدام JSON كصيغة تبادل بيانات أساسية يوفر سهولة في القراءة والدعم، ولكنه قد يكون أكبر حجماً من صيغ ثنائية مثل Protobuf.

## المخاطر (Risks):
- البطء في الاستجابة إذا لم يتم تطبيق استراتيجية كاش (Caching) فعالة.
- مخاطر أمنية إذا لم يتم تطبيق حماية (Rate Limiting/Auth) بشكل صحيح.

## توثيق الـ API (Swagger/OpenAPI):
- يجب توثيق جميع الـ API endpoints باستخدام معيار OpenAPI/Swagger.
- يتم استخدام مكتبة `darkaonline/l5-swagger` لتوليد التوثيق تلقائياً من الـ Annotations في الكود.
