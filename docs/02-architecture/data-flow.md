# تدفق البيانات (Data Flow)

**لماذا هذا القسم موجود؟**
يوضح هذا القسم المسار الذي تتخذه البيانات من المصدر الخارجي وصولاً إلى المستخدم النهائي، لضمان فهمنا الدقيق لكيفية تحديث ومعالجة وعرض البيانات في النظام.

## تفاصيل التدفق:

1. **جلب البيانات (Ingestion):**
   - يقوم نظام "الجدولة" في Laravel (Cron Job) كل ساعة بالاتصال بـ API خارجي لجلب أسعار الذهب الخام (عيار 24، 21، 18).

2. **المعالجة والحفظ (Processing & Storage):**
   - يتم حفظ الأسعار الجديدة في جدول `Gold Prices` في قاعدة بيانات MySQL.

3. **تطبيق منطق التسعير (Pricing Logic):**
   - عند طلب تطبيق Flutter لبيانات السبايك، يقوم الـ API في Laravel بحساب السعر النهائي لحظياً باستخدام المعادلة:
     `السعر النهائي = (وزن السبيكة × سعر جرام الخام) + المصنعية والدمغة`
     (بيانات المصنعية يتم جلبها من جدول `Pricing Matrix`).

4. **التقديم (Serving):**
   - تُرسل البيانات للـ API في شكل JSON، ويتم تفعيل نظام Caching للاستجابة لمدة 15 دقيقة لتخفيف الضغط على موارد الاستضافة المشتركة.

## المفاضلات (Trade-offs):
- تم اعتماد تحديث البيانات كل ساعة بدلاً من اللحظي لتحقيق التوازن بين دقة البيانات والحفاظ على موارد السيرفر (Hostinger limitations).

## المخاطر (Risks):
- احتمال تأخر تحديث البيانات من المصدر الخارجي.
- احتمال تعطل عملية الجلب (Job) بسبب قيود الذاكرة في الاستضافة المشتركة.

## بدائل تم النظر فيها:
- جلب البيانات في كل مرة يفتح فيها المستخدم التطبيق (تم رفضه لأنه سيؤدي إلى استهلاك سريع لموارد السيرفر وبطء في تجربة المستخدم).
