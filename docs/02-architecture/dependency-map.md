# خريطة الاعتماديات (Dependency Map)

**لماذا هذا الملف موجود؟**
يوضح هذا الملف العلاقات والاعتماديات بين مكونات النظام المختلفة. الهدف هو فهم مدى ترابط النظام (System Coupling)، مما يسهل عملية الصيانة، ويحدد نقاط الفشل المحتملة، ويساعد في تقييم أثر أي تغييرات مستقبلية على المكونات الأخرى.

## الاعتماديات الرئيسية:

1. **الخلفية (Laravel Backend) ⟵ قاعدة البيانات (MySQL):**
   - تعتمد الخلفية بشكل كامل على قاعدة البيانات لتخزين واسترجاع الأسعار، بيانات الدول، والمصنعيات.

2. **الخلفية (Laravel Backend) ⟵ نظام الجدولة (Cron Jobs):**
   - تعتمد الخلفية على نظام الجدولة لضمان تحديث الأسعار بشكل تلقائي ومنتظم.

3. **الخلفية (Laravel Backend) ⟵ مصدر بيانات خارجي (External API):**
   - تعتمد الخلفية على API خارجي لجلب أسعار الذهب الخام؛ أي انقطاع في المصدر يؤثر على النظام بالكامل.

4. **التطبيق الأمامي (Flutter App) ⟵ الخلفية (Laravel APIs):**
   - يعتمد التطبيق على APIs التي توفرها الخلفية لجلب البيانات.

5. **التطبيق الأمامي (Flutter App) ⟵ التخزين المحلي (Local Storage):**
   - يعتمد التطبيق على التخزين المحلي (Hive/SharedPreferences) لضمان الوصول للبيانات في حالة عدم توفر الإنترنت.

## المفاضلات (Trade-offs):
- الارتباط بين التطبيق والخلفية (Tight Coupling via APIs) ضروري لعمل النظام، لكنه يجعل التطبيق يعتمد كلياً على توفر الخلفية. تم استخدام التخزين المحلي كحل مؤقت لهذا الارتباط.

## المخاطر (Risks):
- **فشل سلسلة الاعتماديات (Cascading Failures):** إذا فشلت الخلفية في جلب البيانات من المصدر الخارجي، أو تعطلت قاعدة البيانات، فسيتوقف التطبيق عن عرض بيانات محدثة.

## بدائل تم النظر فيها:
- **فك الارتباط الكامل (Decoupling) باستخدام أنظمة الرسائل (Messaging Queues):** تم رفضها لأنها ستضيف تعقيداً كبيراً غير ضروري لحجم المشروع الحالي ولن تتوافق مع قيود الاستضافة المشتركة.
