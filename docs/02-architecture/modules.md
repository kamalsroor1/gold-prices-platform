# الوحدات البرمجية (System Modules)

**لماذا هذا الملف موجود؟**
يوضح هذا الملف المكونات الرئيسية للنظام، ومسؤوليات كل وحدة، والتقنيات المستخدمة فيها، مما يساعد في فهم هيكلة النظام وتسهيل صيانته وتطويره.

## الوحدات الرئيسية:

### 1. وحدة الخلفية (Laravel Backend)
- **المسؤولية:** جلب البيانات، معالجة الأسعار، إدارة قاعدة البيانات، توفير APIs، وتطبيق منطق التسعير.
- **التقنيات:** PHP, Laravel, MySQL.
- **لماذا وجدت:** لتوفير المركز المنطقي والبياني للنظام.
- **المخاطر:** احتمالية وجود اختناقات في الأداء (Bottlenecks) إذا لم يتم تحسين الاستعلامات بشكل جيد.

### 2. وحدة التطبيق الأمامي (Flutter Mobile App)
- **المسؤولية:** عرض الواجهات، التفاعل مع المستخدم، استهلاك APIs، والتخزين المؤقت للبيانات (Offline Caching).
- **التقنيات:** Dart, Flutter.
- **لماذا وجدت:** لتوفير واجهة مستخدم سهلة وسريعة عبر الهواتف الذكية.
- **المخاطر:** تعقيد إدارة حالة التطبيق (State Management) وتوافقه عبر الشاشات المختلفة.

### 3. وحدة قاعدة البيانات (MySQL)
- **المسؤولية:** تخزين البيانات المهيكلة (الدول، الأسعار، المنتجات، القواعد).
- **لماذا وجدت:** لتوفير حل تخزين دائم وموثوق.
- **المخاطر:** احتمالية بطء الاستعلامات مع زيادة حجم البيانات التاريخية.

### 4. وحدة الاستضافة (Hostinger Shared Hosting)
- **المسؤولية:** توفير بيئة التشغيل، إدارة الملفات، وقواعد البيانات.
- **لماذا وجدت:** لاستضافة التطبيق.
- **المخاطر:** قيود صارمة على الموارد (CPU/RAM) قد تحد من قدرة التطبيق على التوسع.

## المفاضلات (Trade-offs):
- اختيار تقنيات موحدة (مثل Laravel) يقلل من تكلفة التطوير، لكنه يفرض علينا قيود إطار العمل المختار.

## بدائل تم النظر فيها:
- استخدام تقنيات أخرى (مثل Node.js) تم رفضها بسبب توفر خبرة أكبر في PHP ولتوافقه الممتاز مع الاستضافات المشتركة.
