# معمارية الخلفية (Backend Architecture)

**لماذا هذا الملف موجود؟**
يوضح هذا الملف الهيكلية البرمجية للخلفية (Laravel)، مما يساعد في توحيد نهج التطوير وضمان قابلية صيانة الكود وتوسعه.

## الهيكلية البرمجية:
يعتمد النظام على هيكلية **Service-Repository Pattern** لضمان فصل المسؤوليات:
- **Controllers:** لاستقبال الطلبات وتنسيق الردود.
- **Services:** لتنفيذ منطق العمل (Business Logic) وحسابات التسعير.
- **Repositories:** للتعامل المباشر مع قاعدة البيانات (Database Abstraction).
- **Models:** لتمثيل الجداول والبيانات.

## المفاضلات (Trade-offs):
- زيادة عدد الملفات (Layers) يجعل النظام منظماً جداً، ولكنه يضيف وقتاً إضافياً للتطوير مقارنة بالنهج البسيط (Fat Controllers).

## المخاطر (Risks):
- تعقيد غير مبرر إذا لم يتم الالتزام بالأنماط بشكل صحيح.

## بدائل تم النظر فيها:
- **Fat Controllers (وضع المنطق داخل الكنترولر):** تم رفضه لأنه يجعل الكود صعب الاختبار والصيانة.
