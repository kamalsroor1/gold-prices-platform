# معمارية تطبيق الموبايل (Flutter Architecture)

**لماذا هذا الملف موجود؟**
يوضح الهيكلية البرمجية لتطبيق الموبايل، لضمان بناء تطبيق قابل للاختبار، التوسع، والصيانة بسهولة.

## الهيكلية البرمجية:
يعتمد التطبيق على معمارية **Feature-First** (التقسيم حسب الميزات) مع نمط **BLoC** أو **Riverpod** لإدارة الحالة (State Management):
- **Features:** كل ميزة (مثل: الأسعار، السبايك، الحاسبة) في مجلد خاص بها.
- **Data Layer:** للتعامل مع الـ APIs والتخزين المحلي.
- **Domain Layer:** لتعريف كيانات البيانات ومنطق العمل.
- **Presentation Layer:** للواجهات (UI).

## المفاضلات (Trade-offs):
- تقسيم التطبيق حسب الميزات يسهل العمل الجماعي، ولكنه قد يؤدي لتكرار بعض الكود المساعد في البداية.

## المخاطر (Risks):
- زيادة تعقيد التطبيق إذا لم يتم تطبيق نمط إدارة الحالة بشكل صحيح.

## بدائل تم النظر فيها:
- **MVC (افتراضي):** تم رفضه لأنه يجعل الكود متشابكاً وصعب الاختبار في التطبيقات المتوسطة والكبيرة.
